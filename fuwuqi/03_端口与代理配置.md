# 03 端口与代理配置

> 本文解释每个端口的含义，以及本地环境 vs 服务器环境的区别。

---

## 一、端口全景表

### 本地 Mac 开发环境

| 端口 | 所在位置 | 用途 | 谁在用 |
|------|---------|------|--------|
| **8080** | Mac 宿主机（由 adb forward 映射） | A端 WebSocket 服务器 | B端手机通过局域网连接 |
| **8081** | Mac 宿主机 | React Native Metro 打包服务器 | 仅开发时，手机通过 adb reverse 加载 JS |
| **5554** | ADB | Android 模拟器 ADB 端口 | adb 命令行工具 |

**关于 `108081`**（你之前提到的）：这不是一个单独的端口，而是 adb 命令参数的写法误记。实际是：
```bash
# Metro 反向代理（让手机的 8081 请求转发到 Mac 的 Metro 服务器）
adb -s <设备ID> reverse tcp:8081 tcp:8081
```

**本地连接路径**：
```
手机B端:8081 ──adb reverse──▶ Mac:8081 (Metro)  [开发 JS 热更新用]

手机B端 ──ws://Mac局域网IP:8080/ws──▶ Mac:8080
                                          │ (adb forward)
                                          ▼
                                   模拟器内APK:8080
```

### 云服务器环境（测试阶段，ws://）— 实际部署版本

| 端口 | 所在位置 | 用途 | 对外开放 |
|------|---------|------|---------|
| **22** | 服务器宿主机 | SSH 管理 | ✓ 仅限你的 IP |
| **8080** | 服务器宿主机（Nginx 监听） | WebSocket 对外入口 | ✓ |
| **18080** | 服务器宿主机（adb forward） | 内部桥接，Nginx → APK | ✗ 只绑 127.0.0.1 |
| **5555** | 宿主机（socat 代理） | ADB 代理端口 | ✗ 只绑 127.0.0.1 |
| **8080**（容器内） | Waydroid 容器 | APK WebSocket 监听 | ✗ 经 adb forward 映射 |

> **与原设计的差异说明：**
> - 原设计测试阶段不需要 Nginx（直接用 adb forward 暴露 8080）
> - 实际：`adb forward` 只能绑定 127.0.0.1，外网无法直接访问，必须加 Nginx
> - adb forward 改用 18080（而非 8080），避免与 Nginx 监听端口冲突

**服务器连接路径（测试阶段，实际）**：
```
手机B端 ──ws://121.40.198.17:8080/ws──▶ Nginx (0.0.0.0:8080)
                                              │ proxy_pass http://127.0.0.1:18080
                                              ▼
                                        adb forward 127.0.0.1:18080→容器:8080
                                              │ (socat+nsenter 代理 localhost:5555)
                                              ▼
                                        Waydroid容器内APK:8080
```

---

### 云服务器环境（生产阶段，wss://）

| 端口 | 所在位置 | 用途 | 是否需要开放安全组 |
|------|---------|------|----------------|
| **22** | 服务器宿主机 | SSH 管理 | ✓ 仅限你的 IP |
| **443** | 服务器宿主机 | HTTPS/WSS 入口（Nginx） | ✓ 全部开放 |
| **80** | 服务器宿主机 | HTTP → HTTPS 重定向 | ✓ 全部开放 |
| **8080**（安全组关闭） | 宿主机 | 仅内部 Nginx → APK 使用 | ✗ 不对外 |

**服务器连接路径（生产）**：
```
手机B端 ──wss://your-domain.com/ws──▶ 服务器:443 (Nginx)
                                           │ TLS 终止（SSL 证书在 Nginx）
                                           │ proxy_pass http://127.0.0.1:8080
                                           ▼
                                     服务器:8080（adb forward 出口）
                                           │
                                           ▼
                                     Waydroid容器:8080 → APK
```

## 二、为什么 APK 内部不需要改

A端 APK（CarScanner）的 WebSocket 服务器始终在 `0.0.0.0:8080` 监听，不感知外部的 SSL 或域名。TLS 终止由 Nginx 完成，APK 完全不需要修改。

## 三、Nginx 配置文件（实际部署版本）

服务器上已部署：`/etc/nginx/conf.d/cardemo.conf`

### 测试阶段（无 SSL，已实际运行）

```nginx
server {
    listen 8080;
    server_name _;

    location /ws {
        proxy_pass http://127.0.0.1:18080;  # 18080 = adb forward 内部端口
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }
}
```

B端设置：`Host = 121.40.198.17`，`Port = 8080`

### 生产阶段 Nginx 配置

位置：服务器上 `/etc/nginx/sites-available/obd-websocket`

```nginx
# 上游：APK WebSocket（通过 adb forward 映射到宿主机 8080）
upstream obd_websocket {
    server 127.0.0.1:8080;
    keepalive 64;
}

# HTTP → HTTPS 重定向
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}

# HTTPS / WSS
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    # SSL 证书（Let's Encrypt 生成）
    ssl_certificate     /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    # SSL 安全配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;
    ssl_prefer_server_ciphers off;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    # WebSocket 端点
    location /ws {
        proxy_pass http://obd_websocket;
        proxy_http_version 1.1;

        # WebSocket 握手必需
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # 透传客户端信息
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 长连接超时（诊断过程可能持续数分钟）
        proxy_connect_timeout 60s;
        proxy_send_timeout 300s;
        proxy_read_timeout 3600s;

        # 禁用缓冲（WebSocket 必须）
        proxy_buffering off;
        proxy_buffer_size 64k;
    }

    # 健康检查
    location /health {
        access_log off;
        return 200 "OK\n";
        add_header Content-Type text/plain;
    }

    # 拒绝其他路径
    location / {
        return 404;
    }
}
```

### 启用 Nginx 配置

```bash
sudo ln -s /etc/nginx/sites-available/obd-websocket /etc/nginx/sites-enabled/
sudo nginx -t        # 语法检查
sudo nginx -s reload # 热重载
```

## 四、adb forward 详解（实际部署）

`adb forward` 是关键的端口桥接命令。实际部署中因为 ADB 通过 socat 代理，命令略有不同：

```bash
# 实际命令（设备 ID 为 localhost:5555，内部端口 18080）
adb -s localhost:5555 forward tcp:18080 tcp:8080

# 查看当前所有 forward
adb -s localhost:5555 forward --list

# 取消 forward
adb -s localhost:5555 forward --remove tcp:18080
```

**重要**：`adb forward` 不是持久配置，以下情况需要重新执行：
- 服务器重启
- ADB 断开重连（容器重启等）

`/opt/cardemo/restart_apk.sh` 和 `startup.sh` 都包含了 forward 命令，日常操作不需要手动执行。

## 五、B端 App 连接配置

B端 App 在设置界面（AppContext.tsx 的 `cloudHost` 和 `cloudPort`）输入服务器地址。

| 场景 | cloudHost | cloudPort | 协议 |
|------|----------|-----------|------|
| 本地测试（Mac 模拟器） | Mac 的局域网 IP（如 192.168.1.50） | 8080 | ws:// |
| 服务器测试（公网 IP） | 服务器公网 IP | 8080 | ws:// |
| 生产环境 | your-domain.com | 443 | wss:// |

在 CloudBridge.ts 的 `connect()` 方法里，当 host 已包含 `ws://` 或 `wss://` 协议前缀时，直接使用；否则自动补全为 `ws://host:port`。所以：
- 测试阶段：输入 IP 地址（自动补全 ws://）
- 生产阶段：输入 `wss://your-domain.com`（包含协议前缀，端口由 URL 决定）
