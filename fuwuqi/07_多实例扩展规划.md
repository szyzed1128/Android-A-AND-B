# 07 多实例扩展规划

> 当前阶段：单 A 实例，单 B 用户测试。
> 本文档是未来扩容时的设计思路，**当前不需要实现**。

---

## 一、现状与扩展目标

```
当前：  1台服务器 → 1个Waydroid → 1个APK → 1个B端用户
目标：  1台(或多台)服务器 → N个A实例 → M个在线B端（M >> N 因为不是所有B同时在线）
```

核心思路：**A实例池（按需分配 + 空闲回收）**

---

## 二、A实例池设计思路

### 2.1 组件

```
B端 App
  │ wss://服务器/ws?token=xxx
  ▼
调度服务（新增的轻量级服务，跑在服务器上）
  │ 分配逻辑：查找空闲的 A实例 → 分配给此 B端
  ▼
A实例池（N个 Waydroid 容器或虚拟机，每个跑一个 APK）
  A1: ws://127.0.0.1:8081
  A2: ws://127.0.0.1:8082
  A3: ws://127.0.0.1:8083
  ...
```

### 2.2 调度服务

调度服务是一个简单的 HTTP/WebSocket 服务（可以用 Node.js 或 Go 实现），功能：

1. **分配**：B端连接时，从实例池取出空闲的 A实例，返回对应的 WebSocket 端口
2. **代理**：直接充当 WebSocket 代理，把 B端 ↔ 对应 A实例 的消息透传
3. **回收**：B端断开后，等待一段时间（如 60 秒）将 A实例标记为空闲

### 2.3 实例隔离方案

**方案 A（推荐，简单）**：多个 Waydroid 容器（如果 ARM64 裸金属支持运行多个 lxc 容器）
```
waydroid_1 → APK_1 监听内部端口 8080 → adb forward 到宿主机 8081
waydroid_2 → APK_2 监听内部端口 8080 → adb forward 到宿主机 8082
waydroid_3 → APK_3 监听内部端口 8080 → adb forward 到宿主机 8083
```

**方案 B**：多台服务器，每台一个 Waydroid，调度服务做路由
```
调度服务 → 服务器A（8080）
         → 服务器B（8080）
         → 服务器C（8080）
```

**方案 C**：Docker + Redroid（允许多个 Android 容器）
```
docker run --device /dev/binder redroid:11.0.0-arm64 --redroid_width=1080 ...
```

### 2.4 B端适配（最小改动）

B端目前连接单个 A实例。调度服务上线后，B端改为：
1. 先 HTTP 请求调度服务获取分配的 A实例地址
2. 再连接到该地址的 WebSocket

B端代码改动极小，仅在连接前增加一个 "获取调度地址" 的步骤。

## 三、容量估算参考

| 规格 | 内存 | 建议 Waydroid 实例数 | 支持并发 B端 |
|------|------|-------------------|------------|
| ecs.g8y.2xlarge (32GB) | 32GB | 4-6 个 | 4-6 个同时在线 |
| ecs.g8y.4xlarge (64GB) | 64GB | 10-15 个 | 10-15 个同时在线 |

每个 Waydroid + APK 实例大约消耗 3-5 GB 内存（APK 本身含 Xamarin 运行时）。

## 四、当前阶段的建议

在实现实例池之前，**先用单实例验证整个业务链路是否稳定可靠**。

当前阶段任务：
- [ ] 服务器单实例部署成功
- [ ] B端（Android + iOS）稳定连接并完成完整 OBD 诊断流程
- [ ] [FLOW] 日志验证全链路正常
- [ ] SSL/WSS 配置完成

达成以上后，再考虑多实例扩展。
