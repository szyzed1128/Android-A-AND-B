# 08 调度系统部署指南

> 本文档记录 scheduler（调度后端）+ agent（本地实例管理器）的完整部署流程。
> 首次在 ecs.g8y.xlarge（阿里云 ARM64）上验证，后续迁移到 AWS r7g.xlarge 同样适用（架构相同）。

---

## 一、整体部署架构（单服务器测试阶段）

```
同一台 EC2
┌─────────────────────────────────────────────────────────┐
│  Redis          :6379  （调度状态存储）                    │
│  Scheduler      :3000  （调度后端，B端通过 Nginx 访问）     │
│  Agent          :4000  （本地实例管理器，仅内部访问）        │
│  Waydroid APK   :8081  （wsPort，Nginx 对外）              │
│                 :18081 （probePort，adb forward 内部）     │
└─────────────────────────────────────────────────────────┘

B端 App → Nginx:3000/scheduler → Scheduler:3000
                                      ↓ HTTP
                                  Agent:4000
                                      ↓ WebSocket
                                  APK:18081（探针）
                                  APK:8081（B端连接，经 Nginx）
```

> 生产阶段：Scheduler 独立服务器，Agent 部署在每台 Waydroid EC2 上。

## 四、部署 Scheduler（调度后端）

### 4.1 上传代码

```bash
# 在本地 Mac 执行
scp -i ~/.ssh/aliyun_hangzhou.pem -r \
  /Users/zed/Documents/Programe/CarUI/NewUI/yun/scheduler \
  root@服务器IP:/opt/cardemo/scheduler
```

### 4.2 安装依赖 & 编译

```bash
# 在服务器执行
cd /opt/cardemo/scheduler
npm install
npx tsc

# 验证编译产物
ls dist/  # 期望：index.js routes/ services/ types/
```

### 4.3 配置环境变量

```bash
cat > /opt/cardemo/scheduler/.env << 'EOF'
PORT=3000
REDIS_URL=redis://127.0.0.1:6379
EOF
```

### 4.4 创建 systemd 服务

```bash
cat > /etc/systemd/system/obd-scheduler.service << 'EOF'
[Unit]
Description=OBD Scheduler Service
After=network.target redis-server.service
Requires=redis-server.service

[Service]
Type=simple
WorkingDirectory=/opt/cardemo/scheduler
EnvironmentFile=/opt/cardemo/scheduler/.env
ExecStart=/usr/bin/node dist/index.js
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable obd-scheduler
systemctl start obd-scheduler

# 验证
systemctl status obd-scheduler
curl http://127.0.0.1:3000/health
# 期望：{"status":"ok","redis":"ok",...}
```

## 五、部署 Agent（本地实例管理器）

### 5.1 上传代码

```bash
# 在本地 Mac 执行
scp -i ~/.ssh/aliyun_hangzhou.pem -r \
  /Users/zed/Documents/Programe/CarUI/NewUI/yun/agent \
  root@服务器IP:/opt/cardemo/agent
```

### 5.2 安装依赖 & 编译

```bash
cd /opt/cardemo/agent
npm install
npx tsc
```

### 5.3 配置实例

根据服务器上实际的 Waydroid 实例数量配置（初始测试：1个实例）：

```bash
cat > /opt/cardemo/agent/.env << 'EOF'
SERVER_ID=server_01
AGENT_PORT=4000
SCHEDULER_URL=http://127.0.0.1:3000
INSTANCES_CONFIG=[{"id":"server_01_inst_1","wsPort":8081,"probePort":18081,"adbTarget":"localhost:5555","packageName":"com.companyname.cardemo","activityName":"crc64b16463db6be126c1.MainActivity"}]
EOF
```

> **端口说明**：
> - `wsPort=8081`：Nginx 对外暴露端口（B端连接用）
> - `probePort=18081`：adb forward 内部端口（Agent 探针用）
> - 需要配套执行：`adb -s localhost:5555 forward tcp:18081 tcp:8080`

### 5.4 创建 systemd 服务

```bash
cat > /etc/systemd/system/obd-agent.service << 'EOF'
[Unit]

[Service]
Type=simple
WorkingDirectory=/opt/cardemo/agent
EnvironmentFile=/opt/cardemo/agent/.env
ExecStart=/usr/bin/node dist/index.js
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable obd-agent
systemctl start obd-agent

# 验证
systemctl status obd-agent
curl http://127.0.0.1:4000/health
# 期望：{"status":"ok","serverId":"server_01","instances":[...]}
```

## 六、配置 adb forward（多实例端口映射）

```bash
# 单实例测试

adb -s localhost:5555 forward tcp:8081  tcp:8080  # 实际没用（通过 Nginx 对外）

# 验证
adb -s localhost:5555 forward --list
```

## 七、Nginx 配置（暴露 Scheduler 给 B端）

B端 App 需要访问 Scheduler API。**复用 8080 端口，通过 `/api/` 路径代理**，无需开放新端口。

在 `/etc/nginx/conf.d/cardemo.conf` 中添加（保留原有 `/ws` 配置）：

```nginx
server {
    listen 8080;
    server_name _;

    # APK WebSocket（原有）
    location /ws {
        proxy_pass http://127.0.0.1:18080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
        proxy_send_timeout 3600s;
    }

    # 调度后端 API（新增）
    location /api/ {
        proxy_pass http://127.0.0.1:3000/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 60s;
        proxy_send_timeout 60s;
    }
}
```

```bash
nginx -t && systemctl reload nginx

# 验证（从宿主机）
curl http://127.0.0.1:8080/api/health
# 期望：{"status":"ok","redis":"ok",...}
```

**端口映射关系**：
```
B端 → 服务器:8080/ws   → Nginx → APK WebSocket（蓝牙命令）
B端 → 服务器:8080/api/ → Nginx → Scheduler:3000（调度 API）
```

**B端地址推导**（`SchedulerClient.ts` 已实现，自动从 `cloudHost` 推导）：
- 用户在 App 中输入 `47.110.246.8`
- 调度地址自动变为 `http://47.110.246.8:8080/api`
- 无需手动配置任何调度地址

## 九、B端配置

B端 App 无需单独配置调度地址。`SchedulerClient.ts` 已实现自动推导：

**用户在 App 设置界面输入服务器 IP（如 `47.110.246.8`）后**：
- CloudBridge 连接：`ws://47.110.246.8:8080/ws`（APK WebSocket）
- Scheduler API：自动推导为 `http://47.110.246.8:8080/api`（同 IP，同端口，不同路径）

两个地址共用同一个 IP 输入，用户只需填一次。

## 十、已知踩坑

| 问题 | 现象 | 解法 |
|------|------|------|
| APK 探针超时 | `getBrands` 超时 | 检查 adb forward tcp:18081 是否建立，APK 是否在运行 |
| Agent 报 bad | 连续5次探针失败 | `systemctl restart obd-agent`，查看 APK 日志定位原因 |
| Scheduler 找不到 Redis | 启动失败 | 确认 redis-server 已启动，REDIS_URL 配置正确 |
| 实例一直是 probing | 健康上报未到达 | 检查 SCHEDULER_URL 是否可达 |

## 十一、从单实例扩展到多实例

### 同一台服务器增加 Waydroid 实例

> 目前架构：1台 EC2 → 1个 Waydroid → 1个 APK
> 目标架构：1台 EC2 → 多个 Waydroid → 多个 APK

每增加一个 Waydroid 实例，需要：
1. 新 adb forward：`adb -s <target> forward tcp:18082 tcp:8080`
2. 更新 `INSTANCES_CONFIG` 增加一条记录
3. 更新 Nginx 增加对应 wsPort 的反代
