## 三、已知问题

### 3.1 socat 进程泄漏（中等）
当前 5555 端口有 **3 个** socat 进程（PID 7384、19762、19785），原因是 startup.sh 被多次执行但 pkill 没完全清理旧进程。功能不影响，但是资源浪费且容易混乱。

### 3.2 adb forward 端口不一致（低）
- `startup.sh` 里做的是 `forward tcp:18080 tcp:8080`
- 当前实际生效的是 `forward tcp:18081 tcp:8080`（Agent 在启动时覆盖）
- Nginx 配置走 18081，与 Agent 一致，实际无问题
- 但 startup.sh 里的 18080 是遗留，与当前配置脱节，建议清理

### 3.3 实例2 未纳入 Agent 管理
当前 agent.env 里只有实例1（port 5555/18081/8080），实例2 尚未注册。

### 3.4 实例2 未设置 adb forward + Nginx 端口
实例2 的 WebSocket 尚未通过 adb forward + Nginx 对外暴露，B 端无法连接。

  │
  ├─ systemd: weston.service
  │     └─ weston --backend=headless-backend.so --socket=wayland-0
  │           └─ 提供 /run/user/0/wayland-0 socket（实例1 需要）
  │
  ├─ systemd: redis-server.service
  │
  ├─ systemd: obd-scheduler.service（依赖 redis）
  │     └─ /opt/cardemo/scheduler/dist/index.js :3000
  │
  ├─ systemd: obd-agent.service（依赖 obd-scheduler）
  │     └─ /opt/cardemo/agent/dist/index.js :4000
  │           └─ 使用 .env 里的 INSTANCES_CONFIG
  │
  └─ systemd: cardemo.service（依赖 weston + waydroid-container）
        └─ /opt/cardemo/startup.sh
              ├─ [1] 确认 weston 在运行
              ├─ [2] waydroid-net.sh start（配置 waydroid0 bridge + dnsmasq）
              ├─ [3] 准备 /run/user/0/pulse/native 等文件
              ├─ [4] D-Bus 启动 LXC 容器 waydroid（实例1）
              ├─ [5] dummy0 + iptables FORWARD 规则

              ├─ [7] 等待 Android boot_completed
              ├─ [8] 安装/启动 APK
              ├─ [9] 等待 WebSocket :8080 就绪
              └─ [10] adb forward tcp:18081 tcp:8080

## 五、回滚顺序

### 5.1 回滚实例2（今日临时变更，不影响实例1）

```bash
# 1. 停止 LXC 容器2
lxc-stop -P /var/lib/waydroid2/lxc -n waydroid2 -k 2>/dev/null || true

# 2. 停止 socat
pkill -f "socat.*5556" 2>/dev/null || true

# 3. 停止 weston-1
pkill -f "wayland-1" 2>/dev/null || true

# 4. 卸载 rootfs（必须按逆序）
umount /var/lib/waydroid2/rootfs/vendor/waydroid.prop 2>/dev/null || true
umount /var/lib/waydroid2/rootfs/vendor 2>/dev/null || true
umount /var/lib/waydroid2/rootfs/vendor 2>/dev/null || true  # overlay
umount /var/lib/waydroid2/rootfs 2>/dev/null || true
umount /var/lib/waydroid2/rootfs 2>/dev/null || true  # ext4

# 5. 释放 loop devices
losetup -d $(losetup -j /var/lib/waydroid/images/system.img | grep -v "waydroid/rootfs " | cut -d: -f1) 2>/dev/null || true

# 6. 删除 binderfs 设备（无法直接删除，重启自动消失；或保留无副作用）
# 注：binderfs 设备不影响实例1，可保留

# 7. 删除 waydroid1 bridge
ip link set waydroid1 down 2>/dev/null || true
ip link delete waydroid1 2>/dev/null || true

# 8. /var/lib/waydroid2 目录可保留（已持久化 LXC 配置），下次启动只需重新挂载
```

## 六、自动化脚本规划

> 以下脚本**尚未编写**，本节为规划说明。

### 6.1 `create_instance.sh <N>`

用于在服务器上创建第 N 个 Waydroid 实例，执行所有手动步骤并输出实例信息。

**输入**：实例编号 N（从 2 开始，1 是原始实例）
**输出**：
- binderfs 设备 `instN-{binder,hwbinder,vndbinder}`（权限 666）
- `/var/lib/waydroidN/` 目录结构
- rootfs 挂载
- weston 进程（wayland-N）
- waydroidN bridge（192.168.25N.1/24）
- LXC 容器 waydroidN（RUNNING）
- socat ADB proxy（127.0.0.1:555N → 容器内 5555）
- adb forward tcp:1808N tcp:8080

**端口规划**（N=2..20）：
```
adbTarget:  localhost:5555+N-1
socat port: 5554+N
probePort:  18080+N
wsPort:     8080+N  → Nginx 对外
wayland:    wayland-N
bridge:     waydroidN（IP 192.168.25N.1/24）
```

### 6.2 `destroy_instance.sh <N>`

逆序停止并清理第 N 个实例（不删除 /var/lib/waydroidN 目录）。

### 6.3 `start_instance.sh <N>`

服务器重启后，重建第 N 个实例的所有临时运行时状态（binder 设备 + overlay 挂载 + weston + bridge + LXC + socat）。

### 6.4 持久化方案（待定）

方案A：systemd template service（`waydroid-instance@N.service`），每个实例一个 unit
方案B：单一 `start_all_instances.sh` 脚本，加入 `After=cardemo.service`
方案C：修改 `cardemo.service` 脚本，让它同时管理所有实例

### 6.5 Nginx 多实例反代配置

每增加一个实例，需添加：
```nginx
server {
    listen 808N;
    location /ws {
        proxy_pass http://127.0.0.1:1808N;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}
```

同时在 agent.env 的 INSTANCES_CONFIG 中追加对应条目。
